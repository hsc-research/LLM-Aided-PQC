# Agent Dashboard

A local, read-only web view of everything the optimization agents are doing:
live simulation output, every proposal/verdict from all three agent tiers,
and running API cost. Safe to leave open in a browser tab while any
orchestrator is running — it only reads log files, never writes.

## Running it

```bash
nohup python3 /mnt/c/PQC/hqc/agent/dashboard.py > /tmp/dash.log 2>&1 &
```

Open **http://localhost:5000** in a browser. It auto-refreshes every 5
seconds — leave the tab open, no manual reload needed.

To restart it (e.g. after pulling a newer version from git):

```bash
pkill -f dashboard.py; sleep 1
nohup python3 /mnt/c/PQC/hqc/agent/dashboard.py > /tmp/dash.log 2>&1 &
```

To check it's actually running:

```bash
pgrep -f dashboard.py || echo "not running"
tail -5 /tmp/dash.log
```

## What each section shows

**Status banner** (top, color-coded) — plain-English summary of what's
happening right now: an agent actively simulating a candidate edit, an agent
between simulations (proposing/applying/synthesizing), or idle with the
outcome of the last run (win or exhausted retries). This is generated by
checking for live `orchestrator`/`xsim` processes, not by parsing intent —
it's always accurate to what's actually running on the machine.

**Summary pills** — one per log source, showing attempt count, win count,
total nanoseconds gained, and (once cost tracking is present in the log)
running dollar total for that tier.

**Verdict legend** (click to expand) — a one-sentence plain-English
explanation of every verdict the agent can produce (`ACCEPTED`, `gate_fail`,
`marginal_*`, `no_action`, `refused`, `retries_exhausted`, etc.), so a
reader doesn't need to know the codebase to understand a table row.

**Live simulation output** — tail of the current/most recent correctness
run (`fullkat_run.log`). `WRONG` lines mean a byte mismatch against the
official NIST answer vectors; `testbench done` with zero `WRONG` lines is a
pass. Includes a staleness warning: if this log hasn't updated in over ~120
seconds while an agent is running, the simulation may be hung (this happened
once from a broken done-handshake edit; the gate now times out at 600s to
prevent it, but the dashboard still flags it in case something new hangs).

**Latency tier** (`agent/mldsa/latency_log.jsonl`) — autonomous
pipelining/retiming attempts. Each row is one propose → apply → verify
cycle. `gate_fail` rows include the model's design reasoning and, when
available, the divergence data that was fed back for the next attempt.

**Latency-preserving tier** (`agent/mldsa/orchestrator_log.jsonl`) — the
original autonomous tier: same-cycle logic rewrites that must produce
identical outputs on identical cycles (no pipelining).

**Cross-design transfer** (`agent/hqc/transfer_log.jsonl`) — the ML-DSA-
learned strategy priors, applied autonomously to HQC blocks the agent has
never optimized before, gated by the HQC known-answer test.

**HQC flight log** (`agent/flight_log.jsonl`) — historical record from the
original HQC accelerator work: every win, refusal, and no-action attempt.

## Cost tracking

Every logged record from a model-calling tier carries `model`, `api_calls`,
and `cost_usd` (cumulative for that run). The summary pills total this per
source. Prices are hardcoded per model in the relevant orchestrator script
(`PRICES` dict) — update there if Anthropic's published rates change.

## Notes

- The dashboard reads log files only; it has no way to start, stop, or
  affect an agent run.
- If you edit `agent/dashboard.py`, restart it (see above) to pick up
  changes — Flask does not hot-reload in this setup.
- Empty tables are normal early in a fresh clone (no runs yet) or after log
  rotation; this is not an error state.
