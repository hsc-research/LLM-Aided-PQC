### F55. Mixed blocking and nonblocking assignment, three sites (VER-134)

**Observed.** `analyze` failed: `Variable '<x>' is the target of both blocking and nonblocking assignments in the same always block. (VER-134)` at `data_path.v:159` (`dout_internal`), `onegen.v:169` and `onegen_ct.v:179` (`state`). Enumerated by analyzing each file alone; no other file failed.

**Done.**

| File | Line | Change | Argument |
|---|---|---|---|
| `data_path.v` | 172 | `dout_internal <=` to `=` | combinational block; last write on that path, settled value unchanged |
| `onegen.v` | 285 | `state =` to `<=` | inside one branch of an `if`/`else if` chain on `state`; nothing later in the block reads it; removes a cross-block simulation race |
| `onegen_ct.v` | 317 | same | same |

All eight copies of each file were byte-identical before and after (Section 5). Same class as ML-DSA F9.

**Verified.** K1. Commit `37e745c`.

### F56. Multiply-driven registers: dual-port memory and `keygen` `rd_x`

**Observed.** `elaborate` failed with ELAB-366 on `mem_dual.v:57`, and warned 73,419 times with ELAB-405. Collapsed to unique sites, ELAB-405 named exactly two nets: `mem` in `mem_dual.v` and `rd_x` at `keygen.v:783`.

- `mem_dual.v` is the FPGA true-dual-port idiom: two clocked blocks each able to write `mem`. Port 1 is live in four instances (`loca_mem` in `fixed_weight_cww.v`, `mem_dual_A` in both `onegen` files, `INTERLEAVED_RED_MEM` in `poly_mult.v`).
- `rd_x` is driven by the main FSM's clocked block (line 558, `s_x_plus_hy`) and by the transfer FSM's combinational block (lines 751 to 785).

**Genus had warned.** The committed Genus log `logs/asic/hqc_asap7_p1000_20260813/base/genus.log` contains `Warning : Signal or variable has multiple drivers. [CDFG2G-622]` on `mem_dual`. The warning was present and was not triaged.

**Done.**

- `mem_dual.v`: both ports merged into one clocked block, port 0 statements first. Unchanged for different-address writes and all reads. On a same-address collision port 1 now wins deterministically; previously a simulator race, and undefined on FPGA BRAM.
- `keygen.v`: line 558 `rd_x <= 1'b0;` deleted. The main FSM waits on `x_transfer_done` (line 490) before reaching `s_x_plus_hy`, so the transfer FSM is in `trx_wait_start` with `start_x_transfer` low and already drives `rd_x` to 0.

**Verified.** K2, cycle counts identical. ELAB-405 on the baseline arm dropped from 73,419 to 0. Commit `4c7747f`.

**Open, not fixed.** The transfer FSM's `trx_done` state assigns neither `rd_x` nor `sel_x`, so the combinational block infers latches on both. They hold 1 there, since `trx_done` is entered only from `trx_tranfer`. Assigning both to 1 in `trx_done` would be value-equal and remove the latches. Deferred to keep this commit to one change.

**Implication for F52 and F53.** The Genus ASAP7 netlists behind those findings synthesized `mem` with two drivers, resolved by Genus in an undocumented way. Those findings need a caveat banner.

### F57. Unsized constant in a concatenation, Barrett reducer (ELAB-369)

**Observed.** `barrett_red_gen.v:118`: `The width of port a_in on instance KM_2 of design karatsuba_small_param_1 is inconsistent with other instantiations of the same design. (ELAB-369)`, then the same for `a_in_reg_out`.

- `.a_in({0,n_in_reg_3})`: the unsized `0` is a 32-bit integer, so the concatenation is 64 bits into a 32-bit port. `KM_1` connects 32 bits.
- `.a_in_reg_out(n_in_reg)`: a 32-bit output into a `` `CLOG2(N) `` bit net (15 or 16 bits).

Vivado and Genus truncated both silently.

**Done.** `.a_in(n_in_reg_3)`, since a narrower connection zero-extends to the same value. `a_in_reg_out` routed into a new `wire [31:0] n_in_reg_w`, then `assign n_in_reg = n_in_reg_w[`CLOG2(N)-1:0];`, the truncation the other tools performed implicitly. The `{0,k_in}` and `{0,t_shift_32}` connections carry the same pattern but are width-consistent across instances, so DC accepts them; left unchanged.

**Verified.** K3 after the first edit, K4 after the second. Commit `8793960`.

### F58. The ASIC optimized arm carried a double driver the FPGA arm never had

**Observed.** On the optimized arm only, ELAB-405 at `encrypt.v:548`, net `cdw_out_addr`:

```
547:  assign cdw_out_addr = xor_add_addr_div;
548:  assign cdw_out_addr = xor_add_addr/COPIES_OF_CDW;
```

`build/joint_design/encrypt.v`, the FPGA optimized tree, has only the first. A grep of `logs/closure` for multi-driven warnings returned nothing.

**Cause.** Appendix A of the Genus port doc records the `xor_add_addr_div` override being reapplied to the ASIC arm "as three insertions". In `encrypt_parallel.v` the assign was a replacement; in `encrypt.v` the original line was never removed.

**Why H16 missed it.** H16 counted override tokens in both trees (3 and 3). A leftover original line contains no override token. Token counts show that something was added, not that something was removed.

**Done.** Line 548 deleted in `asic/arms/hqc_optimized/encrypt.v` only.

**Verified.** Sorted diff against `build/joint_design/encrypt.v` leaves three lines, each an F34 neutral repair (null statement removed, duplicate `pm_out` deleted, duplicate `sel_fw` dropped). `build/` was not edited, so K4 still describes the tested file. D2 elaborates with 0 ELAB-405.

**Implication.** The FPGA +5.8 percent HQC result is unaffected. The Genus ASAP7 optimized netlist (F52, F53) contained the double driver.

### F59. Portability is tool-relative, and the correctness gate is blind to structural defects

Not a measured result. An observation from F55 to F58, recorded for the paper.

- Each defect here was accepted by Vivado and Genus and rejected by DC. The July defect survey and F36 taxonomy were built from Genus error codes, so they could only find what Genus objects to. A third backend surfaced three new classes.
- The KAT cannot detect a multiply-driven net while its drivers agree. F58's double driver passed every gate the agent had.

**Proposal, unvalidated.** Add a DC (or lint) elaborate-and-link stage to `port_gate.py` stage 2, failing on any `Error` or ELAB-405.

### F60. DC success markers are not evidence

**Observed twice.**

1. The first `dc_elab.tcl` printed `ARM_READ_OK`, `ARM_ELAB_OK`, `ARM_LINK_DONE` after every step failed, because `puts` ran unconditionally.
2. After guarding on return codes, `elaborate` printed three errors and returned success, so `ARM_ELAB_OK` printed again.

**Done.** `run_dc.sh` judges a run solely by the log: zero lines beginning `Error` and a `SYN_DONE` line. It writes `STATUS` as `DONE` or `FAIL`.

**Rule.** No DC marker, return code or exit status is evidence of success. Count `Error` lines.

## 7. Method for the PPA table

Requested by Dr. Abideen: per design, baseline and optimized rows with maximum verified frequency, cell area, static, dynamic and total power, and the critical path start register, end register and dominant module.

| Column | Source | Rule |
|---|---|---|
| Frequency | highest tested MET period over a fixed grid | Both arms at every grid point. No binary search (F39), no projection, no interpolation. State the grid |
| Cell area | `report_area`, `Total cell area` | at the reported period |
| Static power | `report_power`, leakage | pW in the report; convert before tabulating |
| Dynamic power | internal plus switching | mW in the report; label vectorless |
| Total power | sum after unit conversion | |
| Critical path | `rpt/timing_worst.rpt` start and end points | Reject any path starting or ending at a port (F13) |
| Dominant module | hierarchical instance prefixes on the worst path, weighted by incremental delay | Requires `-no_autoungroup` |

**Prohibited:** quoting a slack-derived frequency from a single run, comparing DC rows to Genus rows, quoting dynamic power without the vectorless label.
