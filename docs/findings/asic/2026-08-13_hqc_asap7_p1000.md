**These are not closure numbers.** Both arms are MET at the requested period,
which means `syn_opt` optimized to the constraint and stopped. The achievable
period for either arm is below 1000 ps and is unknown. 1000 ps must not be
converted to 1 GHz and reported as Fmax. The 1 ps slack difference between
arms is not a timing result: it is the residue of the tool stopping once the
constraint is satisfied.

**This run does not establish an ASIC timing improvement for HQC.** It
establishes the direction of area and power under a common memory model.

## F52. The HQC baseline binds on a single cone; the accepted edit disperses it

**Observed.** In the baseline arm every one of the 20 reported worst paths
starts at `decap_out_en` and ends in `ENCAP_MODULE_HASH_MEM_q_reg`. One
control signal, one destination register file, twenty reported paths differing
only in endpoint bit.

In the optimized arm `HASH_MEM_q_reg` does not appear in the worst-20 at all.
The reported paths spread across four structures (Q10 to Q13), and the
`decap_out_en` startpoint now accounts for 12 of 20 rather than all of them.

**What was done.** Nothing beyond reading the two committed reports. This is
an observation about the existing arms, not a new experiment.

**How it was verified.** Endpoint and startpoint histograms taken from the
post-`syn_opt` report of each arm, one file per arm. The mapped report was
checked against the post-`syn_opt` report for the baseline arm by diff and is
identical, so the choice of file does not change the result.

**Scope limit.** `report timing -nworst 20` was run without `-unique_pins`.
Genus therefore reports bit-parallel paths through shared logic as separate
entries. Q9 and Q14 should be read as "20 of 20 reported paths through one
cone", not as twenty structurally distinct critical paths. The concentration
is real; the count is a count of report entries.

**Implication for the paper.** This is the direct answer to whether any
sub-block carries a large share of the critical paths, and the answer for HQC
baseline is that one does, completely. It also explains why Q1 shows no timing
gain while Q2 and Q6 do: the edit changed the shape of the critical set rather
than shortening the binding path under this constraint. Whether the dispersal
would pay at a tighter period is untested, and F39 forbids finding out by
closure search.

## F53. Register power dominates under the flip-flop memory model

**Observed.** Registers account for 72.99 percent of baseline power and 76.24
percent of optimized power. The `memory` category is zero in both arms.

**How it was verified.** Read from the two committed power reports.

**Implication.** Inferred memories are mapped to flip-flop arrays, so what the
report attributes to registers includes the memory arrays. This is the same
limitation recorded for ML-DSA in F10 and it means the power figures describe
the flip-flop model, not a design with compiled memories. The relative
difference between arms is the defensible reading; the absolute wattage is
not a chip power estimate.

## What does not exist yet

- **No HQC place and route.** All numbers are pre-layout synthesis estimates.
  Net area is Genus's estimate with no routing.
- **No closure period or Fmax for either arm**, by rule and by F39.
- **No second period point.** Both arms were run at 1000 ps only, so there is
  no same-design sweep and no evidence about behaviour at tighter constraints.
- **No compiled-memory run.** The flip-flop model is the only memory model
  measured.
- **No SLH-DSA ASIC result of any kind.**
- **No vector-driven power.** Q6 is vectorless with default switching
  activity.
