## Gate

Working. `/mnt/c/PQC/slh_sim/a/b/c/d/run_sim.sh`, exits nonzero on failure.

Two checks:
1. Vendor testbench sign-then-verify round trip, verdict parsed from stdout
2. Produced signature diffed against a frozen golden file

Golden reference:
- `/mnt/c/PQC/slh-dsa/gate/golden/SIG_file0_128f_w.hex`
- sha256 `10f35fcc0cc98680d87cf7aaef1479ba359303a84ba2553d69a8b77771bdf2a8`
- 2,141 lines, 36,397 bytes. 2141 x 8 = 17,128 bytes against a 17,088 byte
  SLH-DSA-128f signature, so 40 bytes of tail remain unexplained. Worth
  confirming.

### What the gate does NOT establish

- **It is differential, not absolute.** The golden file was generated by this
  same RTL. It proves an edit changed nothing. It does not prove the baseline
  is correct. Upgrading requires vectors from the NIST reference
  implementation or from Dr. Deshpande.
- **It has never been observed to fail.** A gate that has only ever passed has
  not been shown to be a gate. Corrupt a byte of the golden file and confirm
  FAIL before trusting it.
- **Single configuration.** 128f, SHA-2 only. Five other parameter sets and
  the SHAKE256 family are untested.
- The vendor testbench prints its verdict via `$display` and exits 0 either
  way. The nonzero exit comes from the wrapper, not from `tb.v`.

## Findings: read configuration, not source defects

Three separate read-order requirements. **No SPHINCSLET source was modified.**

### 1. Synthesis needs global includes

`setting.v` and `clog2.v` must be set `is_global_include`. Without this,
Vivado's per-file compilation units leave `PARAM_*` undefined, so
`chain_lengths.v` declares no ports or registers, producing 21 elaboration
errors.

```tcl
set_property is_global_include true [get_files .../setting.v]
set_property is_global_include true [get_files .../clog2.v]
```

### 2. Simulation needs `--relax`

`xvlog` rejects the ANSI port redeclarations at `FSM.v:190,202` as errors.
Vivado synthesis accepts the same construct with a warning. `--relax` clears
it without a source edit.

### 3. Simulation needs `default_nettype` files compiled last

Eight files set `` `default_nettype none `` and never restore it:
`imports/fifo.v` and all seven under `sphincslet/sha/`. In a single
compilation unit the directive leaks into SPHINCSLET's own sources, which
rely on implicit nets. This surfaced as `LR_flag2_pre is not declared` at
`XMSS_FSM.v:228`. Compiling those eight last resolves it.

### Retraction

Earlier in the session, five files were catalogued as carrying portability
defects: `FSM.v`, `hash_mem_interface_sha.v`,
`hash_mem_interface_shake256.v`, `hash_tile.v`, `top.v`. **All were artifacts
of a flat `xvlog` file list in a single compilation unit.** In Vivado project
mode with global includes they are warnings only, and the design synthesizes
with zero errors. That catalogue is withdrawn.

The correct claim is narrower: SPHINCSLET requires specific read
configuration in both synthesis and simulation, and is recoverable by
configuration alone in every case found. This is the same class as HQC F31,
and SLH-DSA is now the third codebase exhibiting it.

### Loose end

`LR_flag2_pre` (`XMSS_FSM.v:228`) is an implicit net, assigned once and
referenced nowhere else. Possibly dead logic. Worth confirming before an
agent edits that module.
